> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy a Quarto multi-page static website to GitHub Pages that surfaces pre-computed LGCP results, live Minneapolis crime data, KDE hotspot maps, and domestic violence education — with nightly automated re-renders via GitHub Actions.

**Architecture:** `03_dashboard.R` houses all data-prep functions (loads `data/MPLS_crime.csv` + `output/lgcp_posterior.rds`, computes KDE, formats posterior summaries). `.qmd` pages call those functions and render to static HTML. A dedicated `refresh_data.R` re-runs `01_data.R` in the GHA job to update the crime CSV without touching the MCMC. Rendered `_site/` is pushed to the `gh-pages` branch; never committed to `main`.

**Tech Stack:** R 4.4+, Quarto ≥ 1.5, leaflet + leaflet.extras (heatmap), plotly, gt, spatstat (KDE), sf, terra, tidyverse, testthat 3.x, GitHub Actions

load_crime_data <- function(path = "data/MPLS_crime.csv") {
  required_cols <- c("year", "Offense", "Y", "domestic_flag",
                     "x", "y", "pop_dens", "pct_pov",
                     "Precinct", "Ward", "occurred_date")
  df <- read_csv(path, show_col_types = FALSE) |>
    mutate(year = as.character(year))
  missing <- setdiff(required_cols, names(df))
  if (length(missing) > 0) stop("Missing columns: ", paste(missing, collapse = ", "))
  df

# ── Annual trend ──────────────────────────────────────────────────────────────

compute_annual_trend <- function(crime_df) {
  crime_df |>
    group_by(year, Offense) |>
    summarise(
      n            = n(),
      pct_domestic = 100 * mean(Y == 1, na.rm = TRUE),
      .groups      = "drop"
    )
}

# ── LGCP posterior ────────────────────────────────────────────────────────────

load_lgcp_posterior <- function(path = "output/lgcp_posterior.rds") {
  if (!file.exists(path)) stop("LGCP artifact not found at: ", path)
  post <- readRDS(path)
  required <- c("samples_comb", "ips_sf", "model_summary",
                "p_int", "p_mark", "n_years",
                "covariates_int", "covariates_mark")
  missing <- setdiff(required, names(post))
  if (length(missing) > 0) stop("RDS missing elements: ", paste(missing, collapse = ", "))
  post
}

# ── KDE heatmap raster ────────────────────────────────────────────────────────
# Returns a WGS84 SpatRaster for use with leaflet::addRasterImage().
# crime_df:  data frame with columns x, y (km, UTM Zone 15N)
# window:    spatstat owin in matching km coordinates
# sigma_km:  KDE bandwidth in km
# offense:   "all" | "domestic" | "nondomestic"

kde_crime_raster <- function(crime_df, window, sigma_km = 0.5,
                              offense = c("all", "domestic", "nondomestic")) {
  offense <- match.arg(offense)
  pts <- switch(offense,
    "domestic"    = crime_df[crime_df$Y == 1, ],
    "nondomestic" = crime_df[crime_df$Y == 0, ],
    crime_df
  )

  ppp_obj <- spatstat.geom::ppp(x = pts$x, y = pts$y, window = window,
                                 check = FALSE)
  dens    <- spatstat.explore::density.ppp(ppp_obj, sigma = sigma_km,
                                           positive = TRUE)

  # spatstat im: v[row, col] where row 1 = bottom y (ascending).
  # terra rast fills top-to-bottom, left-to-right.
  mat_flipped <- dens$v[nrow(dens$v):1, ]  # flip y so row 1 = top

  r <- terra::rast(
    nrows = nrow(mat_flipped),
    ncols = ncol(mat_flipped),
    xmin  = dens$xrange[1], xmax = dens$xrange[2],
    ymin  = dens$yrange[1], ymax = dens$yrange[2],
    crs   = "+proj=utm +zone=15 +datum=WGS84 +units=km"
  )
  terra::values(r) <- as.vector(t(mat_flipped))
  terra::project(r, "EPSG:4326")
}
```

# ── Posterior parameter table ─────────────────────────────────────────────────
# Returns a gt table of posterior summaries for beta, gamma, sigma, tau.
# Parameter labels must stay in sync with covariates_int / covariates_mark
# stored in the RDS (see Task 1 contract).

format_posterior_table <- function(samples_comb, p_int, p_mark) {
  params <- c(
    paste0("beta[",  seq_len(p_int),  "]"),
    paste0("gamma[", seq_len(p_mark), "]"),
    "sigma", "tau[1]", "tau[2]"
  )
  labels <- c(
    "Intercept (intensity)", "Dist. water — intensity",
    "Intercept (mark)",      "Dist. water — mark", "Domestic flag — mark",
    "GP amplitude σ",        "Year RE precision τ₁", "Year RE precision τ₂"
  )

  purrr::map_dfr(params, function(p) {
    s <- samples_comb[, p]
    tibble::tibble(
      Parameter = p,
      Mean      = mean(s),
      SD        = sd(s),
      `2.5%`    = unname(quantile(s, 0.025)),
      Median    = median(s),
      `97.5%`   = unname(quantile(s, 0.975))
    )
  }) |>
    dplyr::mutate(Label = labels) |>
    dplyr::select(Label, Parameter, Mean, SD, `2.5%`, Median, `97.5%`) |>
    gt::gt() |>
    gt::fmt_number(columns = c(Mean, SD, `2.5%`, Median, `97.5%`), decimals = 3) |>
    gt::cols_label(Label = "Parameter", Parameter = "NIMBLE name") |>
    gt::tab_style(
      style = gt::cell_text(weight = "bold"),
      locations = gt::cells_column_labels()
    )
}
```

## What Is Domestic Violence?

Domestic violence is a pattern of behavior used by one partner to maintain power and control over another in an intimate relationship. It encompasses physical, emotional, psychological, sexual, and financial abuse.

## Cycle of Violence

Research documents a recurring pattern in many abusive relationships:

1. **Tension building** — stress accumulates, survivor "walks on eggshells"
2. **Incident** — explosion of abusive behavior
3. **Reconciliation** — apologies, promises to change, honeymoon period
4. **Calm** — incident minimized or forgotten

This cycle can repeat many times and typically escalates in severity over time.

title: "Methods"

## Model

This analysis fits a **marked Log Gaussian Cox Process (LGCP)** to aggravated assault point patterns in Minneapolis, 2020–2022, using the [NIMBLE](https://r-nimble.org) probabilistic programming framework.

### Intensity process

Let $s_i$ denote the location of event $i$. The intensity $\lambda(s)$ follows:

$$\log \lambda(s,t) = \mathbf{x}(s)^\top \boldsymbol{\beta} + \log \rho(s) + W(s) + \delta_{1,t}$$

where $\mathbf{x}(s)$ are fixed-effect covariates (intercept, distance to water), $\rho(s)$ is a population density offset, $W(s)$ is a zero-mean Gaussian process spatial random effect, and $\delta_{1,t}$ is a year random effect.

### Mark process

Each event carries a binary mark $Y_i \in \{0,1\}$ (domestic / non-domestic). Given the event location:

$$\text{logit}\,P(Y_i = 1 \mid s_i) = \mathbf{z}(s_i)^\top \boldsymbol{\gamma} + \delta_{2,t}$$

where $\mathbf{z}(s_i)$ includes intercept, distance to water, and a smoothed domestic-call-type flag.

### Gaussian process

The GP uses a low-rank approximation with $n_K$ adaptive knots (denser in high-crime areas) and exponential covariance $C(d) = \sigma^2 \exp(-\phi \, d)$. The range parameter $\phi$ is estimated via empirical variogram on the raw point pattern. The non-centered parameterization $W^\star = L\mathbf{z},\; \mathbf{z} \sim N(0,I)$ (where $L$ is the Cholesky factor of the knot covariance) improves MCMC mixing.

### MCMC

- **Chains:** 3 parallel chains via R `parallel`
- **Iterations:** 150,000 total; 75,000 burn-in; thinning = 10
- **Posterior samples:** 7,500 per chain
- **Convergence:** Gelman-Rubin $\hat{R}$ on $\boldsymbol{\beta}$, $\boldsymbol{\gamma}$, year REs, variance components

## Data Sources

| Source | Variable | Access |
|--------|----------|--------|
| [Minneapolis Open Data — Crime](https://opendata.minneapolismn.gov) | Aggravated assaults 2020–2022 | ArcGIS FeatureServer API |
| [US Census ACS 2019](https://www.census.gov/programs-surveys/acs.html) | Population density, poverty rate | `tidycensus` |
| [TIGER/Line](https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.html) | Water bodies, roads | `tigris` |
| [OpenStreetMap](https://www.openstreetmap.org) | Police station locations | `osmdata` |
| Minneapolis Neighborhoods shapefile | Study boundary | Checked into repository |

## Coordinate System

All spatial objects are projected to UTM Zone 15N (`EPSG:32615`) then scaled to **kilometres** for NIMBLE. KDE bandwidths and GP range parameters are expressed in km.
